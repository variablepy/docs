---
title: "Error Code Reference"
description: "Machine-readable error codes returned by failed tasks."
---

A failed task returned by [`/getResult`](/endpoints/get-result) has the shape:

```json
{
  "status": "failed",
  "errorId": 1,
  "error": "SOLVE_FAILED"
}
```

The `error` field is a stable, machine-readable code. Match on this field in your integration.

## Error codes

| Code | Description |
| --- | --- |
| `SOLVE_FAILED` | General solve failure. |
| `PROXY_LIMITED` | The proxy appears to be rate limited. |
| `HSW_FAILED` | An hCaptcha HSW-related operation failed. |
| `CAPTCHA_FAILED` | Captcha recognition or processing failed. |
| `SOLVE_TIMEOUT` | The solving process exceeded its allowed time. |
| `EMPTY_TOKEN` | The solver completed without receiving a token. |
| `MAX_ROUNDS` | The solver reached its maximum number of solving rounds. |
| `PROXY_ERROR` | The proxy failed to connect or establish a tunnel. |
| `NETWORK_ERROR` | A network, SSL, TLS, or connection error occurred. |
| `SITE_CONFIG_FAILED` | The target site's captcha configuration could not be retrieved or processed. |
| `BAD_REQUEST` | The solve request was considered invalid internally. |
| `BAD_TASK_TYPE` | The supplied task type is unsupported. Returned with `errorId: 2`. |

## Handling failures

Most errors are transient. For proxy or network-related codes (`PROXY_LIMITED`, `PROXY_ERROR`, `NETWORK_ERROR`, `SOLVE_TIMEOUT`), retry with a fresh proxy. For solver-level codes (`SOLVE_FAILED`, `HSW_FAILED`, `CAPTCHA_FAILED`, `EMPTY_TOKEN`, `MAX_ROUNDS`), retry the task.

`BAD_REQUEST`, `BAD_TASK_TYPE`, and `SITE_CONFIG_FAILED` usually indicate a problem with the request itself. Verify the sitekey, site URL, and task type before retrying.
