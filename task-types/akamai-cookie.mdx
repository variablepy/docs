## Task Type

`AkamaiCookie`

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `siteurl` | string | Yes | Page URL protected by Akamai Bot Manager |
| `proxy` | string | Yes | `http://user:pass@host:port` |
| `user_agent` | string | Yes | User agent the solve runs under |

## Request

```json
{
  "type": "AkamaiCookie",
  "task": {
    "siteurl": "https://www.ups.com/us/en/Home.page",
    "proxy": "http://user:pass@host:port",
    "user_agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/146.0.0.0 Safari/537.36"
  }
}
```

## Price

\$0.30 / 1k solves

## Response

The solution returns the Akamai cookies instead of a token:

```json
{
  "status": "solved",
  "solution": {
    "cookies": "_abck=...; bm_sz=...; bm_s=...; bm_so=...",
    "user_agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/146.0.0.0 Safari/537.36"
  }
}
```

Send `cookies` and `user_agent` together on your own requests. `_abck` is the sensor cookie Akamai expects, so reuse the same user agent or the cookie will not be trusted. `bm_sz`, `bm_s`, and `bm_so` are included when the edge issues them in the same session.

## User agent alignment

A solve runs on a browser fingerprint whose version must match the user agent it claims. If the `user_agent` you send names a browser build we have no matching fingerprint for, the solver aligns it to the closest available build and returns the agent it actually used in `user_agent`.

Always send the returned `user_agent` on your own requests rather than the one you submitted — a fingerprint/version mismatch is exactly what Akamai answers with `403 Access Denied`.
