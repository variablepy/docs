# Vercel Security Checkpoint

Solve the Vercel security checkpoint (Attack Challenge Mode) and get the `_vcrcs` cookie back in the solution.

## Task Types

- `VercelChallengeCookie` — requires your proxy
- `VercelChallengeCookieProxyLess` — no proxy, solved from our IP

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `siteurl` | string | Yes | Full URL that returns the checkpoint, for example `https://example.com/en` |
| `proxy` | string | Yes for `VercelChallengeCookie` | Proxy in `http://user:pass@host:port` format |
| `user_agent` | string | No | User agent hint for the challenge request |

## Request

```json
{
  "type": "VercelChallengeCookie",
  "task": {
    "siteurl": "https://example.com/en",
    "proxy": "http://user:pass@host:port"
  }
}
```

## Price

\$0.80 / 1k solves

## Response

| Field | Description |
| --- | --- |
| `solution.cookies` | `_vcrcs=<value>` cookie to attach to your requests |
| `solution.user_agent` | User agent the cookie was issued to |

## Notes

- The cookie is bound to the IP and user agent that solved it. Send both back with your follow-up requests, and use the same proxy for the same site.
- Solve time is typically 25-90 seconds. Vercel validates browser fingerprint telemetry, so the challenge is executed in a real browser profile (mouse activity included) rather than a plain HTTP replay.
- The checkpoint always answers with `429` plus `x-vercel-mitigated: challenge` and an `x-vercel-challenge-token` header until the visitor is cleared, so treat a `429` on the target site as "not solved yet", not as an API failure.
- Headless browser quality matters: on a low-core host with a slow proxy exit the challenge can take longer than usual. A real browser user agent, residential proxy and a responsive host give the fastest and most consistent results.
